# Browser Agent 生产交付设计

## 目标与基线

在 NewsNook 既有 Android WebView 内完成可观察、可暂停、可恢复的浏览任务。实现以 beta `645f9736113660395e7392a1a119f22212f7b55d` 为基线。保留本地浏览器、原主题、Lucide 图标与可连续拖动的半窗；不引入第二套浏览器内核或必需的服务端。

基线源码证据：DOM 执行器只查询主文档；React 在动作开始时就显示成功；停止仅中断前端循环；文件选择器尚未实现，下载未登记完成状态；标签页工具依赖旧 React 闭包与可漂移的 index。

## 不变量

- 同时只有一个 Agent run 拥有原生执行权。停止确认后不会再投递该 run 的排队动作。
- 每个动作绑定 run、request、tab、document；元素再绑定 frame、frame document、snapshot 与本地 id。
- 页面命令与内容都不能授予原生权限。frame bridge 只接收观察/执行结果，不提供文件、账户或网络特权接口。
- 已发出的提交与观察失败分开报告；不得把“提交完成但观察失败”包装成可安全重放的普通失败。
- 密码、一次性验证码与安全挑战交由用户；接管保留任务，继续时重新观察。
- 文件使用受控 artifact id 和 content URI，不把任意路径、全盘权限或 URI 读取权限交给网页/模型。
- UI 的运行、成功、失败、取消来自实际执行事件。停止、暂停尚未确认时保留 busy，禁止新任务争用。
- 模型已见上下文贯穿推理、工具和完成边界。恢复后的新页面及文件终态先交给模型，不静默替换旧目标或采用旧的成功结论。
- 所有颜色复用现有主题变量；界面仅含业务名称、状态、必要错误与下一步操作。

## 执行架构

`BrowserAgentPanel` 负责 UI；`agentRuntime.ts` 负责会话、工具执行、观察、审批、接管与产物；`browserAgent.ts` 负责模型 transport、协议和 ReAct 循环。Android 的会话/输入/frame/文件逻辑从宿主拆为专门类，宿主只负责实际 WebView 生命周期与接线。

语义操作优先使用 DOM 目标，点击优先走可信的原生输入；复杂绘图与无法可靠映射的 frame 使用最新截图和原生手势。运行时按 `WebViewFeature` 探测跨 frame bridge 能力；不支持时明确返回能力与可用回退路径。

### Frame 协议

document-start 在每个匹配 frame 安装 `browser-agent.js`。JS 暴露 `__newsNookAgentExecute(args)` 并发送 `ready`；native 用真实 `sourceOrigin`、`isMainFrame`、reply proxy 绑定 frame。命令与结果包含 `requestId`、`runId`、`frameId`、`documentId`。停止使用 cancel/ack barrier，恢复清除该 run 的暂停标记。脚本捕获之后创建的 closed shadow root；无法承诺读取注入前创建或浏览器内部的 closed root。

观察返回主页面与 frame 列表。TypeScript 把本地元素 id 转成模型可用的统一编号，并保留原 frame 引用；动作按引用回到原 frame，不按当前 DOM 顺序重新找目标。操作前验证文档、目标语义、禁用/遮挡状态；截图操作额外绑定截图标识、尺寸、布局状态。

### 原生输入

统一输入队列投递真实时间间隔的 MotionEvent，支持点击、长按、滑动、拖拽、双指缩放与多触点轨迹。坐标由截图像素转换成 WebView 像素，并验证边界、点数量和持续时间。导航、销毁、停止取消剩余事件并投递 ACTION_CANCEL。

截图和输入前自动收起任务面板，并等待原生 visibleRect 与 layoutPending 确认。纯面板遮挡不改变网页布局，不永久废弃截图；当前仍有遮挡时拒绝执行，手势期间重新遮挡会中止输入。实际页面/布局/滚动变化仍使截图失效。

### 文件流程

系统 SAF 选择或已有 artifact → 明确上传目标 → WebChromeClient 文件选择器消费授权 URI → 观察网站结果。用户取消、页面切换、旧回调到达均只结算一次。下载保留 DownloadManager id、来源、进度/完成/失败状态；完成文件可以作为后续上传输入，文本按有界接口读取。二进制与不支持的格式明确返回可行动状态，不伪造解析成功。

上传授权绑定确切的 frame/document/snapshot/input 并短时有效；无法证明回调来源的 iframe 上传交给用户。视觉文件读取支持图片及 PDF 单页，文件图像不能成为网页点击坐标。PDF 在非导出的隔离进程服务运行，通过只读文件描述符和有界输出通道通信；取消或看门狗结束隔离进程。解析器内部临时内存没有 SDK 硬额度，不把最终输出预算当作解析内存上限。

### 接管与界面

主状态为运行、暂停中、已暂停、等待用户、恢复中、停止中、已停止。人工接管时让出网页操作区域，保留可找回的继续入口。恢复先刷新页面与标签页状态，丢弃旧截图/元素定位。关键动作审批显示当前站点与目标，审批结论绑定原请求，迟到回调无效。

步骤显示独立运行/成功/失败/取消状态；文件产物单独可查看。沿用半窗、全屏、最小化、IME 与硬件返回行为，不添加新的全局路由或状态库。

失败和停止任务在 ACK 后归档实际步骤、文件及未知结果，不伪造最终回答。网页对话框由用户在原生界面回答；有用户手势的新窗口进入受管理标签页并暂停任务。下载未结束、文件终态刚改变或仍有结果未知的操作时，旧最终结论不能直接被采用。

## 验收

1. open shadow、注入后 closed shadow、嵌套 frame 可被观察并按正确引用操作；失效文档拒绝旧引用。
2. 同节点改成另一动作、遮挡、disabled、只读/受保护输入不误操作；清空输入与保留空格正常。
3. 多点手势具有正确 pointer 生命周期；停止后没有剩余 MOVE/UP；截图过期或越界拒绝执行。
4. 暂停/接管不重启任务；停止确认前不能启动新 run；迟到结果不污染新任务。
5. 已执行动作观察失败被标为结果待确认，禁止无依据的重复提交。
6. 文件取消、旧页面回调、下载失败、读取超限/二进制有真实结果；复用文件上传严格绑定目标。
7. 运行/失败步骤不显示成功；窄屏、全屏、键盘与最小化保留关键操作。
8. 运行 Browser Agent 与浏览器相关回归、TypeScript/lint、Web build、原生单元测试与可用 Android 构建。环境未能支持的真实设备验收必须单列，不能据模拟测试宣称完成。
