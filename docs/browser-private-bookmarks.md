# 浏览器隐私书签：存储与揭示边界

## 用户行为

- 普通浏览时的书签保持原存储键 `newsnook:browser:bookmarks:v1`、列表、搜索、删除与清空逻辑不变。
- 开启隐私模式后，「添加书签」只对 `newsnook:browser:private-bookmarks:v1` 执行写入或取消收藏；这是用户主动保存，网页跳转仍绝不自动写历史或书签。
- 隐私模式中的普通书签仍照常可用；额外的隐私书签默认不在 DOM、搜索、结果计数、清空书签或首页快捷访问中出现。
- 隐私模式的书签页标题在 900 ms 的相邻点击窗口内连续点按五次，才临时展开隐私书签分区。任何其他页内点击中断序列。展开后再次五连击可以隐藏。
- 离开书签页、切换到普通模式或退出浏览器后解锁状态丢弃；不会写入本地配置，也不会跨会话恢复。
- 展开后，隐私书签与普通书签分区展示，支持独立删除与二次确认清空。普通「清空书签」只清空普通分区，绝不清除隐私书签。

## 架构与安全界限

- `browserBookmarks.ts` 负责域模型、存储分区及点击序列，不依赖 React。`BrowserWorkspace` 是唯一的读写协调者：先写本地存储成功，再发布 UI 状态；写入失败不能显示「已收藏」。
- `BrowserPlacesPanel` 只负责临时解锁状态及渲染，它根据当前模式和五次操作同时判定是否允许显露；收起时隐私 URL 不进入 DOM，隐藏状态下也不生成站点图标的外部请求。
- 原有普通书签不迁移、不丢弃。旧版隐私浏览曾保存到普通书签键中，因为没有来源标记，升级后保持原样，不猜测、不自动转移用户数据。
- 两个本地分区都不加入账户同步、快捷访问或常规设置备份。显式收藏可以跨应用重启保留，不随隐私会话退出而删除。
- **五次点击不是密码、加密或访问控制。** 隐私 URL 仍以普通本地存储形式存在；能读取应用私有数据或控制调试环境的人可以绕过此 UI 隐藏。不能向用户宣称该功能提供加密保险库级保护。
